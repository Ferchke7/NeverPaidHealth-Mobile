# Мастер-план разработки мобильного приложения `duda.uz` (`duda-mobile`)

Данный документ содержит пошаговый план превращения текущего прототипа `duda-mobile` (Kotlin Multiplatform + Compose Multiplatform для Android и iOS) в полноценное продакшн-приложение, синхронизированное с бэкендом `https://duda.uz/api/v1`.

---

## 1. Аудит текущего состояния (Проблемы, которые мы решаем)

1. **Полное отсутствие сетевого слоя и авторизации:**
   - В `build.gradle.kts` подключён `Ktor 3.0.2`, но в коде нет ни одного `HttpClient`.
   - Нет экранов входа/регистрации, нет хранения JWT-токена, нет привязки данных к аккаунту пользователя.
2. **Полное отсутствие сохранения данных (In-Memory Only):**
   - `NeverPaidRepositoryImpl.kt` хранит все данные в `MutableStateFlow` в оперативной памяти. При перезапуске приложения все тренировки, замеры веса, задачи и настройки пропадают.
3. **Фейковые экраны без ViewModel и без логики:**
   - `TodoScreen.kt` — нет ViewModel, дни недели (`ПН 26 .. ВС 1`) и 5 задач захардкожены внутри `@Composable`. Нажатие на другие дни недели ничего не меняет. Нет изоляции выполнения по датам (`YYYY-MM-DD`), нет добавления/удаления задач, нет таймера фокуса (Pomodoro).
   - `NutritionScreen.kt` — нет ViewModel, кнопка «+ Добавить продукт» просто добавляет в список фейковую строку `"Перекус #5 - Протеиновый батончик и кофе (210 ккал)"`. Нет ввода КБЖУ, нет ИИ-анализа по фото/тексту, нет трекера воды.
   - `ProgramsScreen` — отсутствует вообще. Кнопка «Программы» на главной (`DashboardScreen.kt`) никуда не ведёт. Нет просмотра программ, активации сплита, лайков и всплывающего `ModalBottomSheet` с комментариями (как в Instagram).
4. **Симуляция вместо аналитики в `ProgressViewModel` и `HistoryViewModel`:**
   - В `ProgressViewModel.kt` столбцы объёма (`"W-4" to 8200.0 .. "Current" to 14200.0`) и сеты по мышцам (`"Chest" to 14`) захардкожены константами и не зависят от проведённых тренировок.
   - В `HistoryViewModel.kt` матрица активности за 84 дня генерируется формулой `dayIndex % 7 == 1`.
   - В `NeverPaidRepositoryImpl.kt` ИИ-тренер отвечает заготовленными фразами через `when { lower.contains("bench") -> ... }`.
5. **Отсутствие мультиязычности (`RU` / `UZ` / `EN`) и старый нейминг `NeverPaidHealth`:**
   - Половина интерфейса на русском, половина на английском. Нет переключения языков (`RU` / `UZ` / `EN`).

## 2. Пофазовый план реализации (Roadmap)

### Фаза 1: Инфраструктура, Сеть (`Ktor`), Персистентность и Локализация (`RU` / `UZ` / `EN`)
- [x] **1.1. Ребрендинг и чистка конфигурации:**
  - Переименовать `rootProject.name` в `duda-mobile`, обновить заголовки и тему под бренд **`duda.uz`**.
- [x] **1.2. Система мультиязычности (`core/i18n/`):**
  - Создать `DudaStrings` и полные переводы для **Русского (`ru`)**, **Узбекского (`uz`)** и **Английского (`en`)** языков.
  - Обернуть корневой UI в `CompositionLocalProvider(LocalDudaStrings provides currentStrings)`.
- [x] **1.3. Локальное хранилище (`core/storage/DudaLocalStorage.kt`):**
  - Реализовать персистентное хранение на Android (`SharedPreferences` / JSON-файл в `filesDir`) и iOS (`NSUserDefaults` / `NSDocumentDirectory`) через `PlatformBridge`.
  - Сохранять: JWT `accessToken`, профиль пользователя, `UserPreferencesData` (язык, единицы измерения, таймер отдыха), активную незавершённую тренировку (`ActiveWorkout`), кэш тренировок, задач (`Todos`), логов питания и замеров тела.
- [x] **1.4. Сетевой клиент `Ktor` (`core/network/DudaApiClient.kt`):**
  - Настроить `HttpClient` с `ContentNegotiation(kotlinx.serialization.json)`.
  - Автоматически добавлять заголовки `Authorization: Bearer <token>` и `Accept-Language: <lang>`.
  - Реализовать обработку ошибок RFC 7807 (`ProblemDetails`) и перехват `401 Unauthorized`.

### Фаза 3: Тренировки, Шаблоны и Программы с комментариями (`features/dashboard`, `features/workout`, `features/programs`)
- [x] **3.1. Главный экран тренировок (`DashboardScreen.kt`):**
  - Привести к правилу **«1 экран = 1 задача»**: убрать визуальную перегрузку, оставить карточку активной программы/сплита дня, быстрый старт пустой тренировки и список шаблонов (`Routines`) с возможностью создания нового шаблона через `ModalBottomSheet`.
- [x] **3.2. Экран активной тренировки (`WorkoutScreen.kt` & `WorkoutViewModel.kt`):**
  - Подтягивать реальные предыдущие веса и повторения (`previousWeightKg`, `previousReps`) из последней завершённой тренировки с этим упражнением.
  - Автоматически сохранять состояние активной тренировки в `DudaLocalStorage` при каждом изменении подхода.
  - Добавить звуковое оповещение и вибрацию при завершении таймера отдыха.
  - При завершении тренировки (`Finish`) отправлять `POST /api/v1/workouts` и обновлять локальную историю и рекорды.
- [x] **3.3. Экран Программ и Сообщества (`features/programs/`):**
  - Создать `ProgramsContract.kt`, `ProgramsViewModel.kt`, `ProgramsScreen.kt`.
  - Загрузка программ тренировок (`GET /api/v1/programs` + встроенный каталог проверенных сплитов PPL, Upper/Lower, Full Body, 5x5).
  - Возможность активировать программу (`activeProgramId`), просматривать упражнения каждого дня и запускать тренировку дня.
  - Лайки программ и **Instagram-style `ModalBottomSheet` для комментариев** (`ProgramCommentsSheet`): просмотр ветки комментариев, ответы (replies), лайки комментариев и отправка нового комментария внизу шторки.

### Фаза 4: Дневной План (`Todo`) с изоляцией по датам и Pomodoro (`features/todo`)
- [x] **4.1. Реальная MVI-архитектура для Плана (`TodoContract.kt`, `TodoViewModel.kt`, `TodoScreen.kt`):**
  - Использовать `kotlinx-datetime` для генерации реальной полосы дат вокруг сегодняшнего дня и выбора любой даты (`selectedDate: String` в формате `YYYY-MM-DD`).
  - **Строгая изоляция прогресса по дням:** каждая задача хранит `completedDates: Set<String>` (для регулярных задач) или `targetDate: String` (для разовых задач). Выполнение задачи сегодня отмечает только сегодняшний `YYYY-MM-DD`, а завтра день начинается с 0% без потери истории за сегодня!
  - Честный подсчёт дневного прогресса (`completedCount / totalCount`), текущей серии дней (`streakDays`) и лучшего рекорда серии (`bestStreakDays`).
- [x] **4.2. Управление задачами и Фокус-таймер (Pomodoro):**
  - `ModalBottomSheet` для создания и редактирования задачи (название, целевой показатель, категория: Тренировка / Питание / Восстановление / Фокус, приоритет, регулярность).
  - Встроенный **Pomodoro Focus Timer** (25 мин фокус / 5 мин перерыв) в отдельной шторке `ModalBottomSheet` со звуковым сигналом и автоматической отметкой задачи по завершении.
  - Синхронизация с `/api/v1/todos` и `/api/v1/activity-logs`.
